# Pausio — feature adoption review per upstream open-source project

**Decision memo (12 Nov 2026).** Scope: evaluate the *specific features* worth integrating into Pausio's existing Python/FFmpeg editing engine, versus features to adapt later or deliberately exclude. This is a design and prioritization decision; it implements **no** video FX runtime. Companion references: [comparative implementation research](VISUAL_FX_AUTOMATION_RESEARCH.md), [motion architecture](VISUAL_MOTION_EFFECTS_PLAN.md), [agentic plan](AGENTIC_EDITING_PLAN.md), [visual FX preset contract](../configs/visual_fx_presets_v1.json). All functionality decisions below are proposed, not claims of current Pausio support.

## Executive decision

**Integrate principles and small ideas, not whole editor runtimes.** The main product target is editable, reproducible talking-head AI/social videos, with a calm/natural default and optional more energetic pacing. Keep Python+FFmpeg, Pausio's existing source-time KEEP/caption/audio command tape, local-first media and future external ChatGPT/Claude Chat as creative agent. Do not embed Gemini/other model inference API calls, Remotion, a second editor state, an arbitrary FFmpeg filter tool or unrestricted media downloading.

Order by user-visible benefit and dependency:
1. **MVP — First working effects:** source/KEEP anchored transform events, manual punch-in/out + slow push and 9:16 crop anchor, reliable FFmpeg preview/final parity, FX lane and inspector. This is the foundation, not an optional preliminary experiment.
2. **Automation v1:** detect objective candidate moments using existing cuts, real ASR phrase/word boundaries and duration; versioned preset profiles, deterministic budget/spacing conflict resolver and *proposal preview* that does not alter project without approval.
3. **Creative enhancements:** optional ratchet for enumerations, caption word emphasis, static/b-roll overlays, scene-change proposals and contextual transitions. No blanket xfade after every pause trim.
4. **Smart framing:** optional offline face/subject tracking with smoothing, safe-zone checks, low-res/face-absent fallback and licensing review; optional speaker switching later.
5. **Further scope:** multiple takes + auto-arrange, speed ramps, advanced transitions/motion graphics, speaker-based layouts, multi-source B-roll recommendation after basic media library and multi-project support.

## 1. Feature-by-feature decision for each upstream

### A. auto-editor — [source](https://github.com/WyattBlue/auto-editor), [actions](https://github.com/WyattBlue/auto-editor/blob/master/docs/src/docs/actions.md), [transitions](https://github.com/WyattBlue/auto-editor/blob/master/docs/src/docs/transition.md)

Useful concrete ideas: timeline-region **classification** (silent/normal/custom labels) separated from **action selection**; composable per-region speed/zoom/volume/overlay actions; animated keyframes/easing; per-transition guard that refuses short removed intervals and missing handles; broad editor export support.

| Feature | Decision | Pausio-specific adaptation |
| --- | --- | --- |
| Observation -> region labels -> effect actions | **Adopt P0** | `CandidateSignal` classes (`cut_boundary`, `phrase_emphasis`, `scene_change`, `face_reframe_needed`) with evidence, not auto-editor's numeric labels directly. Feed one project-local proposal engine. |
| Animate zoom with keyframes/easing | **Adopt P0** | Only bounded typed `video.transform.*` events; FFmpeg filter generated by Pausio with source-to-output mapping. |
| Transition min-cut/handle eligibility | **Adopt P1** | Hard cut default; only show xfade/dip when valid handles and separate audio/caption safety checks permit. |
| Automatic speed changes / speed ramps | **Later P2** | Risk of changing word timing, caption alignment and voice naturalness. Audio pitch-preserving stretch requires dedicated contract. |
| Full transition catalog, motion/rotations/spin | **Avoid MVP** | Too much style noise, inconsistent preview, performance and accessibility risks; many kinds have editor-export-specific semantics. |
| Replace Pausio with auto-editor timeline/CLI | **Reject** | Duplicates canonical reducer, local ASR and FFmpeg renderer; conflicts with import/export and Undo/Redo. |

**Distinct contribution:** the *rules engine* and transition eligibility logic.

### B. add-zooms — [source](https://github.com/louisedesadeleer/add-zooms), [zoom engine](https://github.com/louisedesadeleer/add-zooms/blob/main/scripts/zoom_lib.py), [skill](https://github.com/louisedesadeleer/add-zooms/blob/main/SKILL.md)

Code directly expresses three types of movement: one-frame punch in/out, smooth Ken Burns push, and stepped `ratchet` for lists. It expands an event map into temporal keyframes and computes a zoom envelope. The project intentionally avoids overusing effects and leaves breathing room at 1×.

| Feature | Decision | Pausio-specific adaptation |
| --- | --- | --- |
| Punch-in/out on cut or chosen word | **Adopt P0 — first effect** | Exact frame-aligned step between scale 1× and bounded crop (not necessarily a smooth ramp); hold and reset configurable. |
| Slow Ken Burns push | **Adopt P0** | 2–3 typed keyframes with duration/easing, anchor manually chosen or conservative fixed default. |
| Ratchet zoom ladder for 2–4 listed items | **Adopt P1** | Trigger only from user/ChatGPT semantic markers or high-confidence structured list timing, never blindly count ASR words. |
| Zoom envelope and conflict resolution | **Adapt P0/P1** | Their `max(zoom curves)` is a useful idea; Pausio should *prefer deterministic interval priority/nonoverlap* and remap to KEEP segments. Blind max could cause unexpected prolonged zoom/scale stacking. |
| Single global time-based zoom filter string | **Reject** | Breaks across removed source gaps, edits/Undo, multi-clip source changes and VFR. Store explicit accepted keyframes, not runtime expressions. |
| Automatic semantic choice from local ASR | **Limit** | ASR provides timestamps, not a reliable understanding of key takeaways. Only user/ChatGPT/Claude Chat may provide semantic emphasis tags. |

**Distinct contribution:** a small, effective *vocabulary of reusable effect primitives*.

### C. talking-head-jumpcut-zoom — [source](https://github.com/georgilusikov/talking-head-jumpcut-zoom), [skill](https://github.com/georgilusikov/talking-head-jumpcut-zoom/blob/main/SKILL.md), [critic code](https://github.com/georgilusikov/talking-head-jumpcut-zoom/blob/main/tools/thz_critic.py)

Has live-speaker vs synthetic-avatar profiles; uses a restrained 1× / 1.08× / 1.16–1.18× shot ladder and proposes quality gates such as headroom, face size, blur, gaze/eyes, visual scale diversity and post-render independent inspection.

| Feature | Decision | Pausio-specific adaptation |
| --- | --- | --- |
| Controlled 3-level shot scale | **Adopt P0/P1** | Make shot-size progression optional in Naturale/Educativo; explicit values in profile, not hard-coded universal constants. |
| First frame / face crop / sharpness checks | **Adopt P1** | Separate measurable QC flags for output frames. Missing/low-confidence detection => `unknown`, **never** automatic `PASS`. |
| Independent QA of encoded final video | **Adopt P1** | Inspect actual MP4 rather than simply trusting intended keyframes, including face bounds, black/frozen frames, caption overlay, A/V and output hash. |
| Eye blink, gaze, pose and synthetic-avatar cleanup | **Later P2/P3** | High false-positive risk; depends on licensed, tested on-device CV and diverse real clips. |
| Artificial 4-act dramaturgy and universal shot timing | **Do not impose** | This would force unwanted zooms. Real footage and creator preference should calibrate maximum density, not mandatory density. |
| Treat reported critic checks as proven video validation | **Reject** | Some checks in the upstream sample are prefilled/hardcoded; cannot import those 'PASS' claims as measurements or scientific evidence. |

**Distinct contribution:** effect quality *critic and restrained ladders*; treat project as experimental.

### D. ai-video-reframing — [source](https://github.com/idopinto/ai-video-reframing), [planner](https://github.com/idopinto/ai-video-reframing/blob/main/smartcrop/plan.py), [render](https://github.com/idopinto/ai-video-reframing/blob/main/smartcrop/render.py)

Tracks subjects/faces; chooses a primary track, then uses a hold/follow/smoothing planner, producing a per-frame crop trajectory rendered by FFmpeg `sendcmd`. Code notes limitations: horizontal-only movement, one main subject, missing cut detection and rotation edge cases.

| Feature | Decision | Pausio-specific adaptation |
| --- | --- | --- |
| Track + hold near motion dead zone + smooth catchup | **Adopt P1, optional** | Create local `subject_trajectory` observations with confidence/time; convert to sparse editable crop keyframes. Prevent jitter. |
| Center fallback and no-track behavior | **Adopt P1** | No face or multiple plausible faces => preserve central crop or ask user to select subject; never snap unpredictably. |
| Face safety / crop containment | **Adopt P1** | Consider forehead/chin, subtitles/overlays and aspect-ratio output; cap zoom for low-res footage. |
| Per-frame `sendcmd` crop update | **Consider P1** | Efficient technique, but renderer must use Pausio-generated validated numeric commands and handle VFR/source mapping; prefer sparse keyframes where possible. |
| Bundling YOLO/BoT-SORT and downloading weights automatically | **Block pending license/privacy/performance review** | MIT repository uses Ultralytics AGPL-3.0 components and independent model licenses. Evaluate a suitable locally licensed detector, e.g. MediaPipe/OpenCV with verified terms; opt-in only. |
| Speaker-aware multicam switching | **Not from this repo** | Main planner picks one subject per clip; requires a dedicated diarization-linked multi-person engine later. |

**Distinct contribution:** subject-aware *camera framing*, not semantic effect placement.

### E. AutoBroll — [source](https://github.com/andriidrok1/autobroll), [timeline model](https://github.com/andriidrok1/autobroll/blob/main/src/timeline.ts), [editor state](https://github.com/andriidrok1/autobroll/blob/main/editor/store.ts), [B-roll](https://github.com/andriidrok1/autobroll/blob/main/src/Broll.tsx)

Per-clip source-relative transform keyframes with eased interpolation; real timeline/inspector/undo, multi-take editing, transcript-aware caption emphasis, B-roll from user's own assets or stock. MCP exposes project and frame inspection; actual app uses external Gemini/Pexels keys.

| Feature | Decision | Pausio-specific adaptation |
| --- | --- | --- |
| Source-anchored keyframes and inspector | **Adopt P0** | Per-KEEP/cut-segment keyframe track with scale/x/y, easing and handles; one command reducer, not parallel React state. |
| Undo/redo and regeneration preserving manual edits | **Adopt P0** | Proposal IDs, accepted/rejected decisions, manual lock, diff on rerun. Existing Pausio history is canonical. |
| Preview frame to model/agent | **Adopt P1** | Timecoded frame/contact-sheet tools for ChatGPT/Claude Chat, with explicit data sharing consent. |
| Own-asset-first B-roll with 3 layouts (full/inset/top) | **Adopt P1/P2** | Pair with private content-addressed media library, license metadata, typed overlays and local thumbnails. |
| Selective word accent + face-safe caption placement | **Adopt P1** | Reuse existing Pausio caption engine and ASR, not WhisperX replacement. Word accent and position are typed events. |
| Multi-take auto-arrange and duplicate-take suggestions | **Later P2** | Needs multiple video sources, stable source IDs and transcript reconciliation; do not wedge it into single-source KEEP model. |
| Background music ducking | **P1 in audio WP3/WP4** | Useful but separate from Visual FX; use existing audio mixer and measured LUFS. |
| Remotion renderer, Gemini/Pexels API integration, unscoped MCP writes | **Reject as Pausio defaults** | No second renderer, model provider API keys or implicit external asset fetch. Avoid 'last write wins' collisions; require project revision and user approval. |

**Distinct contribution:** *editor UX and unified state*, plus safe agent-oriented observations—not a reason to replace FFmpeg.

### F. PySceneDetect — [source](https://github.com/Breakthrough/PySceneDetect), [README](https://github.com/Breakthrough/PySceneDetect/blob/main/README.md)

Provides content-based, adaptive and fade/threshold detectors; configurable thresholds, minimum scene lengths and frame extraction. Good for observing actual edits/B-roll footage. Does not determine where an artistic transition belongs.

| Feature | Decision | Pausio-specific adaptation |
| --- | --- | --- |
| Hard cut / scene boundary observation | **Adopt P1** | Optional Python module to annotate B-roll and imported multi-shot footage; cache by source SHA + settings. |
| Adaptive detector for rapid camera movement | **Adopt P1** | Lower false scene cuts than naive content threshold; quality test against face movement and flashes. |
| Fade/dissolve detection | **Consider P2** | Helpful for preserving transitions already in imported footage, not for deciding to add new ones. |
| Automatic segmentation of single talking-head footage on each frame difference | **Avoid** | Too noisy; Pausio already knows the editor's KEEP cuts. |
| Mandatory dependency for every import | **Reject** | One-person videos can run without scene detection; only import where feature actually benefits. |

**Distinct contribution:** trusted *scene observations*, not rendering/transitions.

### G. Clipcast — [source](https://github.com/prismosoft/clipcast), [tracking](https://github.com/prismosoft/clipcast/blob/main/wiki/4-Face-Tracking-and-Auto-Framing.md), [camera switch](https://github.com/prismosoft/clipcast/blob/main/clipping/studio/render_camera_switch.py), [transitions](https://github.com/prismosoft/clipcast/blob/main/clipping/studio/transitions.py)

Python video stack has a detailed face-tracking control surface: detection stride, deadzone, follow smoothing, jitter and snap thresholds; camera-switch layout guided by diarization; podcast split-screen; transition asset caching/downloading; glitch effects.

| Feature | Decision | Pausio-specific adaptation |
| --- | --- | --- |
| Tracking tuning controls with sensible defaults | **Adopt P1** | Advanced-only options for crop stabilization, confidence and scene reset; keep simple presets in normal UI. |
| Diarization + speaker-aware camera switch | **P2, only interview/podcast format** | Reuse Pausio diarized transcript when available; local faces/speaker association needs manual override and evidence. |
| Split-screen and picture-in-picture | **P2** | Useful for multi-speaker/b-roll, not minimum single-person reel. Typed layout/transform events. |
| Effect/transition asset pool | **Adapt P2** | Use locally imported, rights-cleared assets from Pausio media library. No background web download. |
| Random transitions / YouTube URL import / glitch default | **Reject** | Unpredictable results, media licensing/network risk, SSRF and CPU burden; contrary to calm, safe local-first editing. |
| Full camera-switch renderer and model stack | **Reject** | Large overlapping Python/FFmpeg implementation and optional heavy face models; instead port a small interface design with licensing review. |

**Distinct contribution:** later *multi-speaker auto framing* and user-tunable tracking, not default social editing.

## 2. What each Pausio preset should actually enable

Preset values in `configs/visual_fx_presets_v1.json` are existing **design-only limits**; this table is the proposed eventual behavior. Max/min are caps, not target counts. An empty proposal list is a valid success.

| Capability | Naturale (default) | Educativo | Dinamico (opt-in) | Personalizzato |
| --- | --- | --- | --- | --- |
| Hard jump cuts from silence KEEP plan | Preserve | Preserve | Preserve | Preserve |
| Punch-in on eligible cut or selected phrase | Sparse (≤3 events/min total) | Selective (≤6/min) | Faster changes (≤10/min) | Bounded user setting |
| Zoom scale | Typical 1.08–1.16× | 1.10–1.22× | 1.12–1.28× | Bounded ≤1.3× |
| Smooth Ken Burns push | Rare, max 1.10× | On concept/insight, max 1.13× | Selective, max 1.16× | Configurable |
| Ratchet step-list zoom | Off | On **only with explicit 2–4 item marker/evidence** | On with evidence | Toggle |
| Kinetic word emphasis | Off/default minimal | A few selected words | A few more, no every-word flash | Toggle |
| Video transitions | Hard cut only | Contextual short dissolve when legal | Contextual short dissolve/dip | Allowlist |
| Reframe face | Optional static safe anchor | Optional tracking | Optional tracking | Permission + safety bounds |
| Automatic B-roll suggestions | Off | Optional local assets | Optional local assets | Optional |
| Source-frame / chat semantic emphasis | Optional marker from chat/user | Optional | Optional | Optional |
| Default action | **Suggest & review**, no auto-apply | **Suggest & review** | **Suggest & review** | **Suggest & review** |

**Product controls:** choose **Style** (Naturale / Educativo / Dinamico / Personalizzato) independently from **Mode** (Off / Suggerisci / Anteprima automatica non salvata). Offer simple controls for intensity, frequency and type (Punch/Push/Transizioni) in normal UI; advanced folds open easing, ramp/hold, face confidence, ASR/prosody weights, transition handles, output format and caches. The current JSON has style-specific guardrails and numerical limits but **does not yet encode feature toggles or support UI editing**; extend it deliberately in the next command/schema design, with v2 schema migration and validator tests, rather than claiming such toggles already work.

## 3. Initial implementation slices and dependency order

| Slice | Repo contribution | Pausio deliverables | Gate / acceptance |
| --- | --- | --- | --- |
| **S0: model first** | AutoBroll keyframes, add-zooms primitive events | Versioned `video.transform.add/update/remove`; effective KEEP/source time mapping, exact source/revision/project identity, motion conflict constraints and JSON migration | Pure replay, stale revision rejection, Undo/Redo, no extra renderer; security docs |
| **S1: manual visual MVP** | add-zooms + AutoBroll | Real 1-frame punch vs smooth push, source-safe crop/pan, inspector, Video FX lane and FFmpeg filtergraph at 540×960 preview + 1080×1920 final | Synthetic FFmpeg pixel checks, real video visual review, Playwright 320/390/1440, no caption movement |
| **S2: cut-driven automation** | auto-editor rules, THZ QC ladder | `suggest_visual_fx` read-only preview of candidate timestamps from KEEP/cut and available ASR; presets + budgets + stable conflict resolution; explicit acceptance only | Different profiles produce different, *plausible* proposals; no evidence => none; never override manual edits |
| **S3: quality/prosody/scene** | THZ independent QA, PySceneDetect | Actual source/encoded-output QC, optional audio onset emphasis, scene markers, optional ratchet with explicit structured list markers | Measured checks, no fabricated pass or semantics; no unintended speech/scene loss |
| **S4: framing + transitions** | ai-video-reframing, Clipcast tracking, auto-editor transition guard | Optional local face track, smooth reframe, short contextual dissolve/dip with validated source handles and audio policy | License-approved detector, face-safe preview, variable-FPS and rotation tests, no speech duplication |
| **S5: agent/expanded workflow** | AutoBroll MCP/frame inspection and own B-roll | Scoped MCP propose/list/apply FX, frame observations, own media B-roll overlay, captions accents; later multi-take and interviews | Requires authenticated public gateway (#38) for web; user consent; revision, source SHA and full undo/redo, no arbitrary network |

Keep **S0–S2** tightly focused on *one talking-head video with its existing Pausio KEEP timeline* and no external models. Do not block them on PySceneDetect, MediaPipe, YOLO, Remotion, B-roll search, cloud API keys or multi-source video ingestion. Defer feature flags until actual code exists; do not add inactive UI controls.

## 4. Failure modes to explicitly design against

- **False precision:** ASR word position is not proof a word deserves emphasis. No transcript = no word-aligned zoom; no audio = no prosody. A model's semantic marker is a proposal, not an authenticated instruction.
- **Zoom stacking/overlong holds:** a naive `max` zoom envelope can accumulate to a constant close crop; clamp count and duration, resolve conflicts before render and show actual proposed keyframes.
- **Across-cut animation:** when Pausio removes a pause, transforms cannot interpolate from source time before to source time after that removed gap. Split or reject at every KEEP boundary.
- **Source resolution/face clipping:** crop scale constrained by original pixels, output ratio, user/subject movement and subtitle safe-zone; no tracking needed if center works.
- **Transitions injuring speech:** source handles may include intentionally removed audio; do not restore sounds/words merely to make xfade look smooth. Verify actual audio and preserve spoken words.
- **Editor races:** local Studio vs future chat agent must not last-write-wins. Project revision/source hash and atomic transaction, human proposal diff and valid undo/redo required.
- **License/privacy/security:** do not pull arbitrary transition assets or YOLO weights, embed arbitrary filter expressions, expose local Studio to Internet or attach public PR workflow to self-hosted runner. Respect independent library licenses and user rights for B-roll.
- **Fake QC:** report factual computed metrics (frames, crop face box, sharpness) with unknown states; never populate PASS without measurement. The THZ prototype is an interesting idea, not a production-grade certified critic.
- **Excessive creativity:** an automatically filled fixed quota makes videos look mechanical. Keep breathing room, allow *zero* FX, preserve tone and let the creator reject each suggestion.

## 5. Pilot acceptance and decision to expand

**Video set:** 3 real creator recordings (natural outdoors, calm educational, energetic hook), 1 portrait vs landscape pair, 1 no-audio reference, 1 video with 2 speakers. Keep assets private.

**Pilot review:** each style should have recognizably different pacing but no automatically overbusy edits; manually review 20–30 proposed effects with creator. Track approval rate, corrections, face/word timing issues, whether cuts look artificial, time saved, rendered MP4 A/V sync and preview/export geometry. Evaluate on *actual output*, not only candidate JSON. Exit gates: all accepted FX reproduce from project history; no unapproved project mutation or source replacement; no media uploaded without consent.

**Implementation choice after pilot:** If simple cut/word heuristics produce too many weak proposals, do not add more weights blindly: move semantic decisions to the already-planned ChatGPT/Claude Chat agent or require creator-provided markers. Use advanced CV/scene algorithms only when they demonstrably correct framing or edit quality.
